# はじめに
LLMに異なるゲームエンジンで同じ仕様書からゲームを作成させたときの、実装結果やトークン消費量などの比較です。ゲームエンジンは、自作した[KaniVolcanoEngine](https://zenn.dev/otinpan/articles/a2215fcf315987)とオープンソースの[Bevy](https://bevy.org/)で比較します。どちらもRust製でECSを採用しています。

## 2つのエンジンの違い
どちらもEntityにComponentを追加し、Systemでデータを扱うECSを採用しています。Bevyには競合しないSystemを並列実行できる仕組みがあります。KaniVolcanoにはファイバーとスレッドを使用した、独自のジョブシステムがありますが、ユーザが明示的に並列処理やシステムを構築する必要があります。

BevyはグラフィックスAPIとしてwgpuを使用しているため、複数プラットフォームに対応しやすくなっています。対して、KaniVolcanoEngineはVulkanを使用し、描画処理を細かく実装・調整することが出来ます。
![](/images/KaniVolcano/Bevy_Kanivolcano.png)

APIに関しては、Bevyは汎用的な機能と抽象化を多く提供し、KaniVolcanoEngineは比較的直接的なAPIと限定された機能を提供しています。

# 方法
## 手順
1. Neverballの仕様書を作成させる
(別エージェント)
2. エンジンのAPIと仕様書を調査し、実装方針を作成させる
3. 実装方針を`PLAN.md`に保存させる
4. ゲームを実装させる
5. ビルドおよび基本動作を確認し、ここまでを結果として記録する
6. トークン消費量、時間、FPSを記録し終了

2~5までをBevyとKaniVolcanoEngineのそれぞれで行い、比較します。

## 仕様書の作成
仕様書はオープンソースの[Neverball](https://neverball.org/)の実行ファイルをもとに作成しています。LLMがREAを通して実行ファイルを解析し、同時に仕様書を作成してもらっています。

Neverballと各エンジンで作成されたゲームを比較することにより、LLM生成ゲームがどれほど精度が良いのかということを体感することが出来ます。

| 指標 | Bevy | KaniVolcano |
| --- | --- | --- |
| ツール呼び出し | 263回 | 77回 |
| `Get-Content` (ファイルの読み込み) | 95回 | 31回 |
| `rg` (検索) | 37回 | 14回 |

* `Get-Content`と`rg`がBevy側で多かったため、実装時に既存コードを確認する操作がBevyの方が多い
* Bevy側でビルドやエラーへの対応が多かった。これは開発時間の増加にもろに影響していそう

Bevyの方がコード探索、確認、ビルド、修正に関する操作が多いことが分かります。KaniVolcanoEngineはScene・Component・Systemを中心とした比較的直接的なAPIを持ちます。また、機能も少なくLLMが自由に実装できます。このようなAPI設計の違いが、LLMによる実装やエラー修正の難易度に影響を与えた可能性があります。ただ、API調査時間はほとんど同じであり、KaniVolcanoEngineのAPIそのものが理解しやすかったとは断定できません。

# 考察
今回は同一のNeverball仕様書をもとに、LLMを用いてBevyとKaniVolcanoEngineでゲームを再実装しました。

その結果、KaniVolcanoEngineはBevyと比較して、
* 初回実装の総トークン消費量が約60.3%少ない
* 開発時間が約65.4%短い
* 生成されたコードの規模はBevyが3,004行、KaniVolcanoEngineが3,320行であり、大きな差はない

ということが分かりました。

Codexの実行ログを分析したところ、Bevy側ではファイルの参照・検索、ビルド、コード修正などのツール操作が多く確認されました。特に、ツール呼び出し回数はBevyが263回、KaniVolcanoEngineが77回と差がありました。

このことから、開発効率の差は単純なコード生成量ではなく、ビルド・検証・修正を含む開発プロセスの違いによって生じた可能性があります。

その要因として、エンジンの依存関係やコンパイル負荷、API設計、LLMによる実装方針などが考えられます。ただし、今回の実験だけでは各要因の寄与について特定することはできません。

また、初回実装の平均FPSはBevyが20.66、KaniVolcanoEngineが22.05であり、大きな差はありませんでした。ただし、測定条件の差や試行回数の少なさから、実行性能の優劣については断定できません。

以上より、今回のNeverball再構築タスクでは、KaniVolcanoEngineを使用した方が少ない時間とトークン数で初回実装を完了できたことが分かりました。


# 感想
考察や結論が少し曖昧になってしまいましたが、趣味で行っている実験なのでご容赦ください。

もともとは、LLMに自作ゲームエンジンのAPIを使わせてゲームを作成させたところ、予想以上にうまくいったことがきっかけでした。そこから、「他のゲームエンジンを使った場合はどうなるのだろう？」と気になり、今回の比較実験を行いました。

実験回数は各1回のみであり、結果の再現性や一般性を保証できるものではありません。それでも、今回の条件ではエンジンによって開発時間やトークン消費量に大きな差が見られ、LLMによるゲーム開発の効率について興味深い結果が得られたと思います。

今後も、LLMが扱いやすいゲームエンジンやAPIの設計について、いろいろ試していきたいです。
